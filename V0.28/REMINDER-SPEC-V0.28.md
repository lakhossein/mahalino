# REMINDER-SPEC — Mahalino+ V0.28

## ۱) مدل داده (`S.reminders[]`)
```js
{
  id: 'RM-<base36><rand>',     // یکتا
  title: string(≤70),          // عنوان (بدون محدودیت موضوع)
  desc: string(≤140),          // توضیح اختیاری
  due: number(ms),             // تاریخ+ساعت سررسید
  rec: 'once'|'weekly'|'monthly',
  done: boolean,
  status: 'open'|'done',       // با done همگام
  src: 'auto'|'manual',        // منبع ساخت
  chat: string|null,           // شناسهٔ گفت‌وگوی مرتبط (E22.restoredId هنگام ساخت)
  createdAt: ms, updatedAt: ms,
  notified: boolean            // اعلان این دوره صادر شده
}
```
سقف ۵۰ (حذف قدیمی‌ترین انجام‌شده با toast صادقانه). سازگاری: یادآورهای قدیمی E25 (`{id,title,due,amt,done}`) در `E28.remNorm()` (هنگام بوت) به مدل کامل ارتقا می‌یابند. `amt` قدیمی حفظ می‌شود.

## ۲) تشخیص خودکار (`E28.remAuto`) — قاعده‌محور، بدون LLM
- فقط وقتی فلو فعالی باز نیست (`E21.noFlow`).
- نیت: «یادم بنداز/یادم بینداز/یادآور کن/یادآوری کن/یادآور بگذار/یادم باشه/…».
- استخراج زمان (`E28.remParseWhen`):
  - `E21.dateFromText` (امروز/فردا/پس‌فردا/جمعه/ISO) بازاستفاده می‌شود؛
  - «X روز|هفته|ماه دیگر/بعد» →today+X؛
  - روزهای هفته (شنبه…جمعه) → نزدیک‌ترین وقوع آینده (+۹:۰۰)؛
  - «اول هر ماه» → یکمِ ماه بعد ۹:۰۰ با `rec='monthly'`؛ «هر هفته» → weekly؛
  - ساعت: «ساعت ۱۰[:۳۰] [صبح|ظهر|بعدازظهر|عصر|شب]» با تبدیل ۱۲→۲۴؛ بدون ساعت صریح → ۰۹:۰۰.
- عنوان = پیام منهای کلمات نیت/تاریخ (`E28.remTitleFromText`).
- **تاریخ/ساعت هست + عنوان** → ثبت خودکار + کارت تأیید با اکشن «یادآورها».
- **نیت بدون تاریخ** → سؤال شفاف‌سازی (`E28.remPend`)؛ پاسخ بعدی اگر زمان داشته باشد ثبت می‌شود؛ اگر فقط عنوان باشد عنوان گرفته می‌شود؛ «انصراف» لغو می‌کند.
- **نیت بدون عنوان** → پرسش عنوان.
- **جلوگیری از تکرار:** عنوان یکسان + سررسید در بازهٔ ±۱ ساعت → «این یادآور قبلاً ثبت شده است».

## ۳) ساخت دستی
- عبارت طبیعی (همان مسیر خودکار)؛
- دکمهٔ «یادآور جدید» در دفتر یادآور → مینی‌فلو E25 (عنوان→سررسید→مبلغ اختیاری→تأیید)؛
- «یادآورها» از چیپ‌های کشف و منوی حساب.

## ۴) مدیریت (`CBACT.remMenu28`)
- فیلترها: همه / گذشته / امروز / هفتهٔ پیش‌رو / انجام‌شده (`E28.remF`).
- هر ردیف: عنوان + دورهٔ تکرار + برچسب «خودکار» + سررسید (و «گذشته» برای overdue با حاشیهٔ کهربایی) + اکشن‌ها:
  - **انجام شد** (`remDone28`) → done؛ برای تکرارشونده، دورهٔ بعدی بلافاصله ساخته می‌شود؛
  - **تعویق** (`remSnooze28`) → +۱ روز و `notified=false`؛
  - **ویرایش** (`remEdit28`) → مودال عنوان/توضیح/سررسید (`2026-11-10` یا `2026-11-10 10:30`)؛
  - **حذف** (`ACT.remDel/remDelOk`) → مودال تأیید.
- جست‌وجوی متنی: از فیلترها + عنوان کوتاه؛ جست‌وجوی زندهٔ آزاد در ردیف‌ها برای نسخهٔ بعد گزارش شده (Not Implemented — پایین).

## ۵) زمان‌بندی و اعلان
- `ppmTick` (۴ ثانیه) wrap شد → `E28.remTick()`: هر یادآور باز با `due≤now` و `!notified` → toast + `Notification` (فقط با `permission==='granted'`؛ درخواست اجازه هنگام اولین ساخت) + علامت notified. **بدون ادعای اعلان سرویس بیرونی.**
- یادآورها مستقل از باز شدن گفت‌وگوی اصلی کار می‌کنند (tick سراسری).
- ماندگاری: `save()` → `localStorage['mahalino_v18']`؛ پس از refresh و خروج/ورود حفظ می‌شود (تست شده).

## ۶) سازگاری با موتور گفت‌وگو
- تشخیص خودکار در لایهٔ بیرونی `ceSend` قبل از موتورهای دیگر و فقط بیرون فلوها؛ هرگز متنِ درون سناریوها را نمی‌رباید.
- نتیجهٔ ثبت/خطا همگی پاسخ گفت‌وگویی هستند؛ «نبود LLM» پنهان نمی‌شود — تشخیص بر پایهٔ قواعد فارسی است.
