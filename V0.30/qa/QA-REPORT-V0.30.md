# گزارش فنی کنترل کیفیت و آزمون مرورگری محلینو، V0.30

**تاریخ بررسی:** ۲۰ آبان ۱۴۰۵ / 11 November 2026  
**دامنه:** فقط V0.30 و فایل‌های سازنده، آزمون‌ها، بسته‌ها و راهنمای انتشار آن. نسخه‌های تاریخی دست‌نخورده باقی مانده‌اند.  
**محیط مرجع:** GitHub Actions، Chromium واقعی، Playwright و سرور HTTP محلی در Runner.  
**وضعیت انتشار:** **مسدود** تا تکمیل و موفقیت همهٔ ۲۵ مورد اجباری §19.1؛ سبز شدن مجموعهٔ آزمون‌های موجود به‌تنهایی مجوز انتشار نیست.

1. بررسی پرامپت ورودی V0.30، ساختار منابع و قابلیت‌های فعلی HTML؛ تفکیک عملکرد واقعی از نمایش نمونه.

3. کنترل تمام مسیرهای HTML/ZIP و ۱۷ دارایی حیاتی، syntax JavaScript، خروجی build و نبود diff ناخواسته.
4. اجرای مجموعه‌های smoke، functional، conversational، regression، acceptance، scenario و full-journeys در Chromium واقعی روی GitHub Actions.
5. ثبت شواهد مستقل برای هر الزام در `coverage-v030.json`. وضعیت `partial`/`missing` عمداً دروازهٔ انتشار را قرمز نگه می‌دارد.

## ۴. دامنهٔ پوشش الزامات اجباری

منبع دقیق وضعیت، `coverage-v030.json` است. **۱۸ الزام از ۲۵ الزام، پوشش خودکار و PASS دارند؛ ۶ الزام جزئی و یک الزام فاقد پوشش کامل است.** هر مورد فقط زمانی خودکار و تأییدشده محسوب می‌شود که تمام شناسه‌های شواهد آن در یک اجرای واقعی PASS باشند.

مسیرهای باز که مانع انتشارند:

1. **اجاره از ابتدا تا انتها در یک نشست:** تمام مراحل منفرد آزموده شده‌اند، اما سفر پیوستهٔ کشف نیاز، یافتن آگهی، قرارداد، فسخ و تسویه هنوز آزمون مستقل ندارد.
2. **خرید کامل:** قرارداد خرید، پرداخت نهایی و بازیابی از UI به‌صورت یکپارچه اثبات نشده‌اند.
3. **فروش کامل:** پیگیری فروش و قرارداد متناظر در یک مسیر کامل UI اثبات نشده است.
4. **سرمایه‌گذاری کامل:** هدف شخصی، ذخیرهٔ پیشنهاد و پیگیری بلندمدت یکپارچه اثبات نشده‌اند.
9. **ارزش‌گذاری پولی:** زنجیرهٔ خدمت واقعی، تأیید پرداخت، رسید و خروجی باید پیاده‌سازی و آزموده شود؛ پرداخت برای خروجی ساختگی مجاز نیست.
10. **تمام سرویس‌های پولی:** حالت‌های تأیید، لغو، موجودی ناکافی، تکرار و موفقیت برای *تک‌تک* سرویس‌ها باید در UI و نه فقط API آزموده شوند.
18. **اشتراک PDF:** تولید PDF واقعی اثبات شده است؛ ارسال به شخص/دستگاه دیگر یکپارچگی بیرونی نیاز دارد و از HTML محلی قابل‌تأیید نیست.

همهٔ ۲۵ ردیف در manifest باقی می‌مانند؛ نبود یک قابلیت هرگز با حذف آزمون، تغییر مصنوعی انتظار یا اعلام PASS جایگزین نمی‌شود.

## ۵. مرزهای واقعیِ این نسخه

- ورود نمایشی به معنی احراز هویت امن یا OTP واقعی نیست.
- وضعیت signed_internal یک قرارداد رسمی ثبت‌شده در مرجع قانونی نیست.
- انتقال ودیعه/امانی و موجودی «بنا» در این نمونه شبیه‌سازی می‌شود؛ اتصال به PSP و حساب بانکی اثبات نشده است.
- فایل PDF چاپی واقعی است، ولی لینک اشتراک مبتنی بر مرورگر محلی به معنی لینک عمومیِ قابل‌بازیابی در دستگاه دیگر نیست.
- تحلیل محله، آگهی‌ها و ارزش‌گذاری‌های نمونه نباید دادهٔ زندهٔ بازار یا پردازش اسناد واقعی معرفی شوند.

## ۶. قاعدهٔ لازم‌الاجرا برای انتشار

اجرای `bash V0.30/qa/run-quality-gate.sh` باید از ابتدا تا انتها با **exit code 0** خاتمه یابد. اجرای آن شامل بازسازی، صحت دارایی‌ها، هفت مجموعهٔ مرورگری و کنترل پوشش هر ۲۵ الزام است. جریان انتشار Pages در GitHub به این quality gate وابسته است.

مدیر مخزن باید در GitHub Rulesets/Branch Protection، وضعیت `Browser acceptance and reproducible build` را برای `main` الزامی کند، بازبینی Pull Request بخواهد و bypass را مسدود کند؛ فایل Workflow به‌تنهایی جلوی push مستقیم مدیر را نمی‌گیرد.

**تصمیم کنونی:** به `main` ادغام نشود؛ نسخهٔ ۰٫۳۰ به‌عنوان نسخهٔ قابل‌انتشار علامت نخورد تا موارد باز با شواهد مرورگری و آزمون یکپارچگی واقعی بسته شوند.
